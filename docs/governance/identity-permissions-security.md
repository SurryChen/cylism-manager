# 身份、权限与安全

## 用途与边界

本页说明当前平台的安全边界：管理员登录、Kubernetes 与 SSH 凭据、Secret、Agent 授权和审计记录。它不承诺尚未在界面中提供的细粒度组织权限功能。

## 进入位置

安全与访问配置位于系统设置；相关管理行为可在审计日志和操作历史中追溯。

## 准备条件

所有管理员账户应使用受组织管理的认证方式。准备集群、服务器、Registry 或通知凭据时，使用最小权限和独立轮换策略。

## 核心操作

1. 在系统设置审查访问和入口相关配置。
2. 将 Kubernetes、SSH、Registry 和通知密钥保存在受保护的配置或 Secret 中。
3. 对 Agent 功能限定可用运行时和允许执行的操作。
4. 定期审阅审计日志，发现异常后立即轮换可能泄露的凭据。

## 状态与风险

Secret 不应被展示、复制到聊天或写入截图。平台审计只能覆盖通过平台发起的操作；主机和集群还需要各自的访问控制、网络隔离和审计措施。
