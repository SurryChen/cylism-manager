# 项目研发与发行

点击顶部「项目」进入项目中心。同一栏也提供研发工作台、应用部署、应用商城和镜像仓库。项目统一管理产品资料、需求、版本、环境与发行。想法、离线 App、小程序都可以先建项目，无需配置集群或部署。

## 推荐使用流程

1. 创建项目，填写名称、阶段、可选图标与简介。项目英文名可留空自动生成，用于以后部署的命名空间；创建后在总览按需添加仓库、需求、设计和文档链接。
2. 在「待办」记录需求、缺陷、行动，维护优先级与处理状态。正式交付后可关联多个版本。例如同一条登录修复分别随 Web 和安卓发版，可以出现在两次发版的事项清单里。
3. 单端项目直接使用项目默认发布端。安卓、桌面、Web 独立发版时，在「版本 → 管理发布端」分别添加。正式发布后记录发布端、版本号、发版日期和本次交付的事项，按需填写版本说明。各发布端允许使用相同的版本号。
4. 需要后端时，在「环境与部署」创建开发、测试、预发布或正式环境，并选择集群。通过「应用与部署」进入已选中该项目与环境的部署工作区。在部署工作区点击「管理项目环境」即可返回该项目。
5. 验证部署后，可在版本编辑窗口展开「关联部署记录」，选择要留档的部署或平台更新记录。
6. 在「发行 → 发行渠道」可以为渠道指定发布端。新增发行记录时选渠道和测试或正式发行分类，关联该端的版本。测试和提前送审时可先填渠道版本号，正式发版后再补关联。渠道版本号默认沿用所选版本，渠道状态与历史快照独立保留。
7. 在研发工作台汇总待办和发行跟进。项目详情始终支持归档，有环境或应用的项目应先处理部署资源再删除。

## 测试与正式的区别

环境分类明确保存为开发、测试、预发布、正式或待分类，不根据环境名称推断。已有环境可直接编辑分类，不会修改集群、命名空间或已有应用，分类更新不要求集群在线。

发行分类独立于部署环境。新发行记录默认测试发行；正式发行必须显式选择。渠道的正式线上版本、正式待发布版本和进度只从正式发行记录汇总，测试发行不会覆盖它们。列表支持按发行分类筛选，历史快照同时保存当时分类。

部署成功仅表示一次部署完成，不代表验收通过或正式发行。部署回调仍通过应用、环境归属项目，相关部署记录可在该项目版本中选择；不会自动创建正式发行，也不会自动完成迭代。

## 页面与资料管理

项目详情包含「总览、待办、版本、环境与部署、发行」。总览只展示基本信息与有内容的资料链接，不恢复常驻数据库管理区块或公开资料表单。图标仅为可选 URL，未填写时使用名称首字。

版本列表展示发版日期、说明和关联部署，并可按发布端筛选。从版本行可以查看交付事项和渠道发行记录。旧版本的状态、目标和构建资料仍可在详情查看。发行渠道在按钮弹窗中管理，有发行历史的渠道可以暂停。

「环境与部署 → 部署设置」维护项目英文名和默认镜像仓库；已有环境时英文名不可修改。环境名称、部署目标与应用的原有限制保留。

微信小程序和小游戏渠道支持同步微信线上版本、审核状态和运营数据。连接方式见 [微信发行与运营数据](wechat.md)。

在应用详情点击「迁移到其他项目」，可把单个应用归入自己名下的另一项目。在「应用部署」选择目标项目和应用实际运行的环境，即可查看运行版本、发布记录、部署配置和访问入口。应用的集群、命名空间、镜像仓库配置、数据库和自动发布回调沿用原运行环境，迁移无需重新部署。新建应用时仍需选择目标项目自己的环境。目标项目的版本可以关联原部署记录，已有版本也继续保留原来的部署引用。需要迁回时，从应用详情重新选择原项目。

### 迁移运行环境

应用详情的「迁移运行环境」支持从现有部署继续迁到管理项目下的同集群环境。目标必须使用独立命名空间。该流程适用于有就绪探针、使用 ClusterIP 的单容器无状态 Deployment，不处理持久卷或跨集群迁移。

1. 在目标命名空间准备应用引用的配置、密钥和镜像拉取凭据，并确认新旧实例能安全并行。目标项目需要有上线模板和当前发布所用镜像仓库的授权。
2. 选择目标环境并点击「准备目标副本」。系统创建同名 Deployment 和 Service，并检查就绪副本、Service 端点和实际镜像。原工作负载继续运行。可关闭窗口，回到同一目标环境刷新进度。
3. 使用现有网关逐步切流，验证实际访问和业务读写。受管 Ingress 需要由运维人员准备目标规则和证书，并在切换后移除旧规则。共享域名需要先处理共享路由。异常时先将流量切回原服务。
4. 点击「确认接管」后，应用 ID、发布历史和回调地址继续沿用，后续发布使用目标环境。源 Deployment 和 Service 保留，确认稳定后可由运维人员退役。

Cylism Manager 自身使用独立的平台更新流程。在项目基本信息中勾选「关联当前管理平台的发布记录」后，可以在版本中选择平台更新记录。关联不触发平台更新、回滚或发行，也不会自动绑定平台数据库。

## 数据升级与兼容

启动时自动迁移项目与产品资料的唯一关联。产品表保留为项目的生命周期资料，不重新创建需求、版本、渠道或发行记录，因此它们的 ID 和历史链接保持有效。

历史产品仅在关联唯一、自有且未被其他产品共用的项目时自动归入该项目；关联有歧义时创建独立项目并保留原有引用，不移动部署资源。既有自有项目也会补齐生命周期资料，无所有者项目不自动认领。迁移在事务中执行并保存完成标记，重复启动不重复建档。

历史环境与发行记录标为「待分类」，历史发行快照保留。有历史发行记录的渠道，其发行汇总重置为待维护状态，暂停渠道保持暂停；将实际正式发行记录分类为正式后重新汇总。项目、环境、应用、发布、数据库和权限记录保留。

旧产品详情链接会按保存的项目关联进入项目详情，旧项目环境链接进入对应「环境与部署」。历史资料字段、资源引用和旧下一步行动保留，编辑其他资料不清空；旧行动可以转为事项。

已有版本先归入项目默认发布端，可编辑归属。系统保留版本 ID 和原事项关联，也保留无明确发版日期的历史版本，日期可按实际情况补录。

记录使用修订号防止覆盖。微信渠道可以自动登记线上发行。应用构建、提审和发行继续通过各自的发布流程操作。发布前沿用现有数据库备份流程。
