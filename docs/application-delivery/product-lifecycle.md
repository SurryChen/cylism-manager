# 产品研发与发行

在顶部「产品」进入「研发工作台」或「产品中心」。产品可以独立建档，离线 App、小程序和想法无需绑定集群。

## 推荐使用流程

1. 在产品中心维护产品资料、代码与文档链接、发行渠道，以及已有项目或部署组件的关联。
2. 在产品详情「事项」记录需求、缺陷和行动，设置优先级、状态与可选截止日期。尚未确定迭代的事项可以不关联版本。
3. 在「版本」建立本次迭代，记录目标、验收结果、目标日期和代码、构建、制品链接，再将事项安排到该版本。
4. 如产品包含后端，在版本中选择关联的容器部署记录。候选记录来自产品关联的项目或组件，并受原项目权限限制；选择记录不会执行部署。
5. 在「发行记录」选择产品版本与渠道，维护平台版本、Build 标识、审核或发布状态。重新提审可以新建记录；每次编辑都会保存历史快照。
6. 在研发工作台查看受阻和临期事项、待处理发行、等待审核和进行中的版本，并进入对应产品继续处理。

## 模型与已有能力的关系

产品是长期管理对象；产品版本组织一次迭代；发行记录表示一个版本在某个渠道的一次发行。现有 Application 继续表示部署组件，Release 继续表示容器发布记录，通过关联连接到产品版本。

渠道资料保留平台应用标识、后台和公开链接。有发行历史的渠道，其当前进度按最近创建的发行记录汇总，线上版本来自最近一次明确发布的事件。修改旧记录的备注不会覆盖当前线上版本；暂停渠道会退出工作台发行汇总。有历史的渠道不能直接移除，可以暂停。

事项、版本、发行和历史列表均支持后端分页，默认每页 10 条。工作台对当前用户活跃产品作汇总，并按区块分页展示；不生成虚假的运行健康数据。

## 兼容与边界

数据库通过新增表兼容既有产品资料。原「下一步行动」仍可查看和汇总，也可以在事项页手动转为事项；转换与清空原字段在同一事务中完成。

记录通过修订号防止相互覆盖。保存时如提示记录已更新，请刷新列表后重新编辑。版本只能关联本产品的事项、渠道和有权限访问的部署记录。

第一版由用户手工维护研发和发行状态，不接外部平台 API、不自动构建、提审或发布。公开作品资料仍只保存明确选择的公开字段，不自动同步个人主页。
