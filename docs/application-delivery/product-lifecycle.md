# 产品研发与发行

在顶部「产品」进入「研发工作台」或「产品中心」。产品可以独立建档，离线 App、小程序和想法无需绑定集群。

## 推荐使用流程

1. 在产品中心创建产品，只填写名称、阶段、简介和可选标识。进入详情后，在总览中按需维护资料链接和已有项目或部署组件的关联。
2. 在产品详情「事项」记录需求、缺陷和行动，设置优先级、状态与可选截止日期。尚未确定迭代的事项可以不关联版本。
3. 在「版本」建立本次迭代，记录目标、验收结果、目标日期和代码、构建、制品链接，再将事项安排到该版本。
4. 如产品包含后端，在版本中选择关联的容器部署记录。候选记录来自产品关联的项目或组件，并受原项目权限限制；选择记录不会执行部署。
5. 在「发行 → 发行渠道」维护平台标识与链接，再在「发行 → 发行记录」选择产品版本与渠道，维护平台版本、Build 标识、审核或发布状态。重新提审可以新建记录；每次编辑都会保存历史快照。
6. 在研发工作台查看受阻和临期事项、待处理发行、等待审核和进行中的版本，并进入对应产品继续处理。

## 页面与编辑入口

产品详情保留「总览、事项、版本、发行」四个主入口。「发行」下分发行记录和发行渠道；原渠道链接仍可直接进入对应视图。

「编辑基本信息」仅修改名称、阶段、简介、图标和标识。总览只展示有内容的资料链接、关联项目、部署组件、数据库绑定和公开资料区块，内容直接可见，无需点击展开；空区块不再显示占位卡片。服务与资源保留统一的「管理关联」入口，暂无资料链接或公开资料时，在基本信息卡片中提供紧凑的添加入口，补充内容后自动显示对应区块。已有内容分别从「管理链接」和「编辑公开资料」进入编辑。每个编辑弹窗只展示当前区域，保存时保留其他区域和旧行动数据。资源选项只在管理资源关联时读取，创建产品和编辑基本信息不依赖运维资源接口。

渠道表单只维护平台资料及是否暂停发行，线上版本、待发布版本和审核进度由发行记录维护。已有渠道数据保留。公开资料是可选的展示草稿，不要求填写。

## 关联当前管理平台

Cylism Manager 自身使用独立的平台发布流程，不属于普通应用。在产品详情「总览 → 服务与资源 → 管理关联」中勾选「Cylism Manager（当前管理平台）」并保存，即可关联平台自身，无需创建同名项目或应用。

关联后，总览提供平台入口和发布与更新的跳转；新增或编辑产品版本时，可以在「关联部署与平台更新」中选择已有的平台更新记录。平台更新和普通应用部署分别存储关联，编号相同也不会混淆；列表支持统一搜索和分页，只返回镜像、状态、时间等必要信息。编辑基本信息、其他区域和归档会保留平台关联。

取消关联后，平台更新不再出现在该产品的候选记录和版本可见记录中；原关联保留以便重新关联后查看。关联操作只维护产品资料，不触发平台更新、回滚或创建发行记录。数据库新增字段和关联表通过现有自动迁移完成。

## 模型与已有能力的关系

产品是长期管理对象；产品版本组织一次迭代；发行记录表示一个版本在某个渠道的一次发行。现有 Application 继续表示部署组件，Release 继续表示容器发布记录，通过关联连接到产品版本。

渠道资料保留平台应用标识、后台和公开链接。有发行历史的渠道，其当前进度按最近创建的发行记录汇总，线上版本来自最近一次明确发布的事件。修改旧记录的备注不会覆盖当前线上版本；暂停渠道会退出工作台发行汇总。有历史的渠道不能直接移除，可以暂停。

事项、版本、发行和历史列表均支持后端分页，默认每页 10 条。工作台对当前用户活跃产品作汇总，并按区块分页展示；不生成虚假的运行健康数据。

## 兼容与边界

数据库通过新增表兼容既有产品资料。产品基本信息不再填写「下一步行动」和截止日期，具体行动统一在「事项」中管理，事项截止日期按需填写。原「下一步行动」仍可查看和汇总，也可以在事项页手动转为事项；编辑产品资料不会清空旧记录，转换与清空原字段在同一事务中完成。

记录通过修订号防止相互覆盖。保存时如提示记录已更新，请刷新列表后重新编辑。版本只能关联本产品的事项、渠道和有权限访问的部署记录。

第一版由用户手工维护研发和发行状态，不接外部平台 API、不自动构建、提审或发布。公开作品资料仍只保存明确选择的公开字段，不自动同步个人主页。
