# 日常维护与故障处理

## 用途与边界

本页给出从信号到处置的日常运维路径，适用于平台和集群问题的初步判断。具体安装、配置和既有故障条目仍保留在辅助资料中。

## 进入位置

从“可观测与运维”侧栏进入，或查看[既有日常运维](operations.md)与[常见问题](troubleshooting.md)。

## 准备条件

明确影响范围、变更时间和负责人；获取必要的集群与服务器访问权限，但不要共享敏感凭据。

## 核心操作

1. 先查看平台健康、告警和最近发布，确定问题是否与变更相关。
2. 用指标判断资源与节点趋势，再用日志缩小到命名空间、Pod 或容器。
3. 对基础设施问题检查服务器、集群组件和网络；对应用问题回到发布记录和资源详情。
4. 修复后复测访问、告警恢复和关键指标，并记录操作原因与结果。

## 状态与风险

不要在告警尚未定位时同时修改多个层级。对于删除、重启、回滚、数据恢复等高风险操作，先执行备份、审批和最小范围验证。
