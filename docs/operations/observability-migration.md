# VictoriaMetrics / Loki 节点迁移

在指定集群的监控页迁移 VictoriaMetrics，在日志页迁移 Loki。点击“迁移节点”，选择目标节点并确认；关闭弹窗不影响后台任务。“集群任务”保存完整执行日志，刷新页面可重新打开进度。

## 条件

- 组件由平台管理，运行单副本，并已使用绑定到当前节点的本地 PVC。旧 VictoriaMetrics hostPath 需先通过已有入口转换为 PVC。
- 源、目标服务器属于同一个集群，并在平台绑定了 Kubernetes 节点名和 SSH 凭据；支持平台现有 SSH 代理连接。
- 目标节点 Ready、可调度且无阻止调度的污点。两台服务器需要免交互 sudo、GNU tar、sha256sum、bash；目标存储类必须能在该节点创建本地卷。
- 目标磁盘至少具有“源目录大小 × 1.2 + 128 MiB”可用空间。目标卷沿用源卷容量及 StorageClass。

## 执行与恢复

1. 创建持久化集群任务及组件迁移锁。同一集群已有运行任务时拒绝创建；迁移期间拒绝更改组件配置、卸载或再次迁移。
2. 预配目标 PVC 和绑定 Pod，检查 SSH、复制工具、磁盘与空目录。
3. 将源组件缩容为零并等待 Pod 完全退出。此时指标采集/查询或日志存储暂停，暂停期间不保证新增遥测数据完整。
4. 通过 Manager 流式转发 SSH tar 数据，保留文件权限及数值属主。比较源、目标完整目录的规范化 tar SHA-256。
5. 校验通过后切换卷和节点，启动单副本并等待 Ready。Service、保留周期和节点采集器配置保持不变。
6. 完成任务并释放锁。以后调整保留周期会继续使用迁移后的 PVC。

迁移任务和数据复制均不设固定总时限，慢链路只要持续有数据进展就继续传输；连续 3 分钟无字节进展会停止并回退。SSH 建连和握手限制为 30 秒，源组件停止等待最长 5 分钟，目标启动就绪等待最长 15 分钟（含首次拉取镜像）。这些单步骤等待仍有限制，避免异常任务长期占用迁移锁。复制期间源组件停写，低带宽链路可能带来较长的监控不可用时间；应先确认中转节点到目标节点的吞吐，再安排迁移窗口。

迁移窗口内可在组件迁移弹窗查看已传输字节数、总量、速度和剩余时间。复制阶段支持“暂停传输”和“继续传输”：暂停只停止读取当前 SSH 流，保留连接和目标卷，源组件继续停写；继续沿用同一连接。平台进程重启后无法安全续接 SSH 流，页面会隐藏继续按钮，只允许取消并恢复源组件后重新迁移。存储切换开始后不再提供取消，避免回滚覆盖目标已经产生的新写入。

停写前失败不影响源组件。停写后失败会停止目标并恢复快照中的源工作负载；恢复失败时保留迁移锁并自动重试。平台重启后不会重放中断的数据复制：尚未停写的任务结束为失败，中断的复制任务回退，已确认目标就绪的任务只补齐完成记录。

所有源卷、失败任务的目标卷均保留，不自动删除。成功后源卷是迁移时点的旧副本，不会持续同步；恢复失败可结合任务日志人工检查。当前能力针对单副本本地存储，不提供高可用或零停机迁移。

## 2026-11-06 后台迁移

本次一次性脚本保存在 `scripts/operations/observability-background-migrate.py`，在源控制平面由 systemd 单元 `cylism-observability-bg-20261106` 执行。先迁移 VictoriaMetrics，成功后再迁移 Loki，目标为 `ubuntudev`。关闭 SSH 不影响执行；不要重复启动或在平台发起另一轮迁移。

脚本提前准备目标镜像，将停写后的归档按 2 MiB 分块传输，每块最多尝试 8 次，校验归档和完整目录后切换。单组件最长 12 小时，目标就绪等待 20 分钟；失败时尝试恢复源工作负载，所有 PVC 保留。原平台 Loki 任务 32 已按原实例恢复结果结束为回滚，新的手动迁移进度写入服务器日志，不回填成原任务成功。

在腾讯云控制平面查看：

```sh
sudo systemctl status cylism-observability-bg-20261106 --no-pager
sudo tail -f /var/log/cylism-observability-bg-20261106/all.log
```

最终应看到 `ALL SUCCEEDED`，各组件结果保存在同目录的 `*-result.json`。systemd 任务存活本身不代表迁移成功。
