# K3s 兼容性

Cylism Manager 默认使用 Kubernetes API，不要求 K3s。连接成功后，集群节点页面会显示当前识别的平台与版本。

当版本包含 `+k3s` 标记时，平台会额外启用两项 K3s 兼容能力：

- 工作节点加入：保留 SSH 预检和 `k3s-agent` 安装，使用操作员配置的控制面可达地址与 K3s Join Token。
- VPN 兼容诊断：只读取活动 `k3s` 或 `k3s-agent` 单元的 `vpn-auth` 标记，展示不含凭据的已配置状态和服务商分类。

平台不安装、认证或管理任何外部 VPN。若使用 Tailscale 或其他网络工具为 SSH 提供连通性，请在平台外维护节点、凭据和访问策略。

普通 Kubernetes 集群仍可使用服务器台账、SSH 预检、资源管理、存储、证书、制品库和审计能力；K3s 专属动作不会在未识别的集群上启动。
