## Context

现有 VitePress 产品域文档使用 `ScreenshotPlaceholder` 标出建议截图文件名。产品数据来自本地已登录页面，且当前可通过 Edge 全屏模式得到不含标签栏和地址栏的页面区域截图。公开截图仍存在数据泄露风险：主机标识、域名、用户名、凭据、Token 和未脱敏日志均不能进入仓库。

## Goals / Non-Goals

**Goals:**

- 为所有 18 个现有占位位置提供一张真实、任务导向的截图。
- 使用 `1440 x 900` 桌面视口、默认薄荷配色和无浏览器框架的页面区域。
- 以每页标题、关键操作和必要上下文为裁切边界，保留可读的页面结构。
- 将截图与 Markdown 引用纳入文档站自动检查和 VitePress 构建验证。

**Non-Goals:**

- 不拍摄或展示密码、Token、私钥、完整 kubeconfig、真实域名或地址、主机标识、用户名和原始错误日志。
- 不创建虚构数据、装饰图或额外的产品功能说明。
- 不替换没有截图占位符的辅助文档，或强行补全当前无法安全呈现的界面。

## Decisions

### 1. 以现有占位文件名作为截图契约

保留 `assets/screenshots/<domain>/<page>.png` 路径，逐页以 Markdown 图片替换同位置的占位组件。这样侧栏、链接和原有内容结构不变，资源与页面的对应关系也可由检查脚本验证。

备选方案是维持占位组件并让组件在文件存在时动态渲染图片。该方案会使 Markdown 内容不能直接表达图片、增加主题分支，并让资源缺失的错误更晚暴露，因此不采用。

### 2. 使用 Edge 全屏页面区采集并按任务裁切

采用本地 `5173` 的已登录 Edge 标签，进入浏览器全屏后等待工具栏隐藏再截图。每张图只保留与该文档任务相关的页面区，必要时截取一个面板或 Tab，而不是整页的敏感辅助信息。

备选方案是无头浏览器固定视口。它无法复用当前已登录会话，容易落入登录页，故不作为真实产品截图来源。

### 3. 先做内容安全审查，再写入资源目录

每张候选图在落盘前审查：浏览器框架、地址、主机或节点名、用户名、真实域名、凭据、Token、私钥和原始日志均不得出现。无法通过审查的候选图不提交，对应占位保留并在任务中记录原因。

备选方案是事后批量打码。打码既容易遗漏，也会让文档图难以阅读；优先通过页面选择和裁切避开敏感区域。

### 4. 由文档检查锁定已替换范围

检查脚本将验证所有已替换 Markdown 图片均指向 `assets/screenshots/` 内的实际 PNG 文件，并确保没有浏览器框架截图或外部 URL。`ScreenshotPlaceholder` 组件继续保留，以支持未来尚未采集的页面。

## Risks / Trade-offs

- [本地数据可能包含敏感标识] -> 逐张人工审查并使用任务导向裁切；无法安全呈现则不替换。
- [页面状态随采集时间变化] -> 只表达稳定的入口、结构和操作上下文，不以数值、时间或状态为文档承诺。
- [单张图尺寸过大影响加载] -> 保持 PNG 清晰度并在提交前检查文件尺寸；必要时无损压缩，不缩放到影响文字可读性。
- [文档与界面后续演进] -> 通过稳定文件名和自动检查让更新范围可定位；页面变化时重采该页截图。

## Migration Plan

1. 先为资源存在性和 Markdown 图片引用添加失败的文档检查。
2. 按域采集、审查并写入截图，逐页替换占位符。
3. 执行文档结构检查、VitePress 构建和页面视觉检查。
4. 若某图不合格，删除该候选资源并恢复对应占位符，不影响其他页面。
