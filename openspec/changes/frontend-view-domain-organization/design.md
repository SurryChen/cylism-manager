## Context

前端页面目前全部位于 `web/src/views/` 根目录。页面已经按路由领域形成自然边界，但文件仍然平铺，导致应用管理、集群基础设施、Kubernetes 资源、网络和系统设置文件混杂。测试文件与页面同目录的约定需要保留。

## Goals / Non-Goals

**Goals:**

- 使用少量稳定的领域目录降低 `views/` 根目录的拥挤程度。
- 保持页面与对应测试文件相邻。
- 保持现有路由 URL、懒加载行为、组件导入和构建结果不变。
- 让目录结构能够直接反映导航和业务领域。

**Non-Goals:**

- 不改造 `api/`、`components/`、`composables/` 或后端目录。
- 不拆分单个 Vue 文件的模板、脚本或样式。
- 不引入 Pinia、全局 Store、别名系统或新的第三方依赖。
- 不修改业务逻辑、API 请求、UI 文案或权限行为。

## Decisions

### 1. 只对 `views/` 做有限领域分组

将应用页面放入 `views/applications/`，集群页面放入 `views/cluster/`，资源页面放入 `views/resources/`，网络页面放入 `views/network/`，系统设置页面放入 `views/settings/`。Dashboard、Monitoring、AuditLogs、RuntimeManagement、ManagedOCIRegistries、DBAdmin、Login 等跨领域或数量较少的页面继续留在 `views/` 根目录。

备选方案：将所有源码改成完整 feature-first 结构。该方案会同时重排 API、组件和组合式逻辑，迁移范围大且收益不足，因此不采用。

### 2. 测试文件与源文件一起移动

每个已存在的 `*.test.js` 与对应页面保持同一领域目录，避免形成独立测试树，也保持现有测试导入方式和维护习惯。

备选方案：统一迁移到 `web/tests/views/`。这会破坏当前同目录约定，并增加测试与源码之间的路径距离，因此不采用。

### 3. 通过显式相对路径更新依赖

移动到二级目录的页面统一将 `../api`、`../components`、`../composables` 调整为 `../../api`、`../../components`、`../../composables`；同目录页面之间继续使用 `./`。路由文件显式指向新的页面路径。

备选方案：新增 Vite 路径别名以隐藏相对路径变化。当前项目没有统一别名规范，为一次目录迁移引入别名会扩大配置和测试影响，因此不采用。

## Risks / Trade-offs

- [相对导入遗漏] → 使用全仓库搜索检查旧路径，并运行前端测试和构建。
- [懒加载路径错误导致运行时页面打不开] → 对路由动态导入做静态检查，并运行 Vite 构建。
- [目录分组过度导致查找成本反而上升] → 只创建五个领域目录，跨领域和小型页面保留在根目录。
- [历史文档中的旧路径失效] → 仅源码引用属于本次迁移范围；历史 OpenSpec 文档保留原始上下文，不做批量改写。

## Migration Plan

1. 创建领域目录并移动页面、测试和系统设置共享样式。
2. 更新页面内部相对导入和路由懒加载路径。
3. 使用 `rg` 检查旧路径和未解析的同目录导入。
4. 运行前端测试、Vite 构建，并执行 OpenSpec 校验。

回滚方式：恢复本次变更涉及的移动和路径修改即可，不涉及数据或外部系统迁移。
