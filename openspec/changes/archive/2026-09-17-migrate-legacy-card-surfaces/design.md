## Context

`SurfaceCard` 已提供语义容器、三种内边距、可选交互态及头部/操作插槽。它已用于制品库、审计日志、操作历史和系统设置，但其他运维页面仍将全局 `.card` 当作内容面板外壳。`.card` 与 `SurfaceCard` 的基础玻璃样式高度重叠，且现有页面标题区域依赖手写 `.card-header` 结构。

本变更的目标是统一内容面板外壳，而不是重做每个页面的信息架构或让所有视觉表面成为卡片。

## Decisions

### 1. 以 `SurfaceCard` 替换内容面板容器

每个满足以下条件的 `.card` 使用点改为 `SurfaceCard`：它包裹页面级或区域级内容，且不是模态框、告警横幅、指标尺寸元素或单条重复数据记录。调用方使用 `as="section"` 或 `as="article"` 保持原有语义；默认使用 `md` 内边距，表格或分隔网格确有需要时使用 `none`。

节点镜像源规则区作为首个验证点：其现有 `section.rule-workspace` 改为 `SurfaceCard`，标题与说明通过 `header` 插槽承载，表格继续保留在单一滚动容器中。不得改变下发、检查、轮询、删除或弹窗行为。

### 2. 头部结构优先使用组件插槽

有卡片级标题和操作的页面使用 `header` 与 `actions` 插槽。标题文案、说明文字和按钮仍属于页面；组件仅负责两列对齐、换行和间距。原有 `.card-header`、`.card-title` 只在尚未迁移的非卡片内容结构中保留，不能作为新增内容面板的外壳契约。

### 3. 分领域、测试驱动地迁移

迁移按节点镜像源、概览与应用、集群与资源、网络、监控与运行时四组实施。每组先在既有或新增页面测试中断言使用 `SurfaceCard` 并保留关键工作流，再修改模板和局部布局。每组完成后运行该组的前端测试，避免一次跨页面替换掩盖布局回归。

### 4. 最后清理全局 `.card` 外壳

全量搜索确认不再有内容面板依赖 `.card` 后，从 `components.css` 移除 `.card` 的基础表面和移动端 padding 规则。`.metric`、`.modal` 与 `.k8s-banner` 的视觉规则从原有组合选择器中拆开保留，因为它们不是本次共享内容卡片的适用对象。

## Alternatives Considered

1. **只保留 `.card` 并同步样式**：不能统一 DOM 结构、插槽和组件级测试，未来仍会分叉。
2. **把 `.card` 作为 `SurfaceCard` 的 CSS 别名**：Vue 组件不能由 CSS 替代，无法消除手写容器和标题布局。
3. **一次替换所有玻璃表面**：会错误覆盖模态、告警或指标，并扩大纯视觉变更的回归范围。
4. **为每个页面新建专属卡片组件**：增加抽象数量，不能解决共享结构漂移。

## Risks and Mitigations

- **表格边缘、padding 或横向滚动变化**：保留原有 `table-wrap` 与局部 class；需要无内边距的区域明确声明 `padding="none"`，并进行桌面与移动端视觉检查。
- **页内标题、操作区换行变化**：使用组件头部插槽并在窄屏测试中确认操作区可换行、不遮挡表格。
- **旧选择器失效**：迁移前搜索 `.card`、`.card-header`、`.card-title` 依赖；保留必要的内容样式并为受影响页面更新局部选择器。
- **业务回归**：模板改动不触碰 API、路由、状态或事件；每个领域运行其现有行为测试，最终执行完整前端套件和构建。

## Verification Strategy

- 先为节点镜像源和每个迁移领域添加失败断言，覆盖共享组件采用与关键用户工作流。
- 每组完成后运行聚焦 Vitest 测试；全量迁移后运行 `npm test`、`npm run build`、`go test ./...`、`go build ./...`、`openspec validate migrate-legacy-card-surfaces --strict` 与 `git diff --check`。
- 以标准桌面与窄屏视口检查节点镜像源、至少一个表格页面和至少一个带操作头部的页面。
