## Context

三个基础设施页面已经使用 `useAsyncResource` 覆盖了部分列表或概览读取，但操作型请求分散在视图文件中：`Servers.vue` 有服务器保存、探测、导入和解绑；`Cluster.vue` 有驱逐、标签和移除节点；`PersistentVolumes.vue` 有 PVC 创建、迁移、备份、恢复、导入和删除。直接调用使 API 合同难以集中测试，也让错误和取消处理在页面间不一致。

## Goals / Non-Goals

**Goals:**

- 为服务器、集群和存储操作建立完整、可发现的领域 API 边界。
- 将目标相关读取的竞态和卸载取消统一交给既有 `useAsyncResource`。
- 将每种失败保留在其发起操作表面，保留最近成功的列表、详情和弹窗数据。
- 使用 API 合约测试和组件回归测试锁定现有协议与操作体验。

**Non-Goals:**

- 不重写页面布局、确认流程、轮询策略或后端实现。
- 不抽象通用 mutation store、全局错误总线或通用弹窗框架。
- 不在本 change 中迁移其他领域的 API 调用。

## Decisions

### API 按既有基础设施领域归属

- `servers.js` 负责服务器创建、更新、删除、探测、预导入、确认导入和解绑。
- `cluster.js` 负责节点驱逐计划、普通/强制驱逐、重新加入、标签读取与保存、移除检查和移除。
- `storage.js` 负责命名空间、PVC、迁移、备份、恢复、目录导入、导入备份删除和现有存储读取。

每个函数以业务参数在前、可选 request options 在后的形式定义。请求函数保持原 HTTP 方法、路径、query 名称、路径编码、payload 和解包结果。对无 options 的旧调用保留原 API 客户端调用形态，避免无意义地扩大已有测试或嵌入方影响面。

不新增一个宽泛的 `infrastructure.js`：服务器、节点和存储的资源模型、调用者和后续维护边界都已由现有 API 文件表达。

### 读取生命周期保持局部且按目标隔离

现有 `useAsyncResource` 是唯一新增或复用的读取生命周期原语。节点驱逐计划、节点标签、移除检查，以及备份/导入记录读取在打开、切换或关闭目标时取消或忽略过期结果。请求成功后才提交当前目标的数据；失败不清空此前成功显示的结果；`AbortError` 不显示为用户错误。

不把所有 mutation 也包入 `useAsyncResource`：提交操作需要明确的按钮 busy 状态和失败后的表单保留，直接的局部 async action 更符合当前页面模式。

### 错误按操作表面显示

- 服务器保存、删除、解绑与导入错误显示在相关表单、确认框或导入流程中，替换静默的 `console.error`。
- 节点计划、标签、驱逐和移除错误保留在对应抽屉或操作区域，不影响节点列表。
- PVC 创建、迁移、备份、恢复、导入和删除错误显示在各自弹窗或确认区域，不关闭用户可修正或重试的表面。

不建立全局 toast：现有页面已有局部错误文案和表单状态，局部呈现能让操作者知道哪一步失败。

### 测试锁定行为而非实现细节

先为新增领域 API 函数添加路径、方法、payload、编码和 signal 转发测试，再迁移页面。组件测试使用 deferred Promise 验证最新目标胜出、卸载中止和失败后保留数据；针对服务器保存/解绑、节点操作和 PVC 高影响操作验证失败时表单或确认框继续可用。

## Risks / Trade-offs

- [路径或 payload 迁移偏差] → 在 API 单测中断言每个方法、路径、业务参数和 request options。
- [过期弹窗响应覆盖新目标] → 复用 `useAsyncResource` 的 request ID 与 abort 语义，并覆盖快速切换目标测试。
- [更细的错误状态遗漏或隐藏] → 在对应组件测试中断言具体失败文案和仍可见的成功数据/操作表面。
- [变更触及高影响操作] → 只重组客户端调用边界，不改变确认条件、服务端校验或动作顺序，并执行全量前后端验证。

## Migration Plan

1. 添加 API 契约测试和命名函数。
2. 逐页迁移 Servers、Cluster、PersistentVolumes，并补充局部错误与读取取消。
3. 执行前端测试/构建、后端测试/构建和严格 OpenSpec 校验。
4. 前端调用合同未变化，因此无需运行时数据迁移；若发现行为回归，可回退本次前端变更。
