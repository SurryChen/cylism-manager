## 背景

小团队运维多台服务器时，NGINX 站点配置和 SSL 证书管理是高频但易出错的操作。当前依赖 SSH 登录每台机器手工编辑配置、运行 acme.sh，缺乏统一管理平面。本平台通过元数据驱动 + Agent 架构解决此问题。

约束：单用户优先，单 SQLite 数据库，Go 编译的单二进制部署。

## 目标 / 非目标

**目标：**
- 通过 Web UI 管理多台服务器上的 NGINX 站点和 SSL 证书
- SSH 远程部署 Agent，gRPC 长连接下发操作
- NGINX 配置双向同步（元数据驱动生成 + 反向导入）
- acme.sh 证书完整生命周期管理
- 仪表盘概览和操作审计

**非目标：**
- 多用户认证与权限（一期不做，架构预留）
- 非 NGINX 的 Web Server 支持
- DNS 托管服务集成
- Agent 自动升级

## 技术决策

### 1. Agent 通信：gRPC + Protobuf

**选择 gRPC** 而非 REST/HTTP：
- 强类型接口定义（proto），Agent 和 Platform 共享同一份契约
- 原生支持双向流，为后续实时日志、文件传输等场景预留
- Go 生态一等支持，编译时类型安全
- 备选：HTTP REST — 更简单但缺少类型安全和流式支持

### 2. SSH 凭据加密存储

**AES-256-GCM 加密** SSH 密码和私钥后存入 SQLite：
- 加密密钥从配置文件读取，不硬编码
- 备选：不加密 — 安全风险不可接受

### 3. NGINX 配置管理：元数据为主，导入为辅

- 元数据是唯一权威来源，生成的配置文件是产物
- 导入功能仅用于"发现"已有站点，不自动接管
- 用户需显式"接管"（设为 managed=true）后平台才开始管理
- 备选：全双向自动同步 — 冲突解决复杂，容易丢失手动修改

### 4. 技术栈选择

| 决策 | 选择 | 理由 |
|------|------|------|
| 后端语言 | Go | 单二进制部署，系统交互方便，gRPC 原生支持 |
| 数据库 | SQLite | 零运维，Go 原生驱动，单机场景足够 |
| ORM | GORM | 迁移方便，社区成熟 |
| HTTP 路由 | gin | 性能好，中间件生态丰富 |
| 前端 | Vue 3 + Vite | 轻量 SPA，生态成熟 |
| 配置管理 | Viper | Go 标准配置库 |

### 5. Agent 部署策略

- Platform 编译时交叉编译多个目标平台的 Agent 二进制
- SSH 连接后探测 OS/Arch，上传匹配的二进制
- 通过 SSH 远程启动 Agent（优先 systemd service，回退 nohup）
- Agent 启动后 Platform 建立 gRPC 连接，心跳 30s 间隔

## 风险与权衡

- **[Agent 离线]** 被管服务器网络中断或 Agent 进程退出 → Platform 标记服务器 offline，UI 提示，用户可重新部署
- **[acme.sh 不可用]** 目标服务器未安装 acme.sh → Agent 启动时检测，未安装则在 UI 提示用户先安装
- **[NGINX 配置校验失败]** 模板生成配置语法错误 → 校验不通过时拒绝 reload，返回错误详情，不写入文件
- **[SSH 凭据泄露]** SQLite 文件被读取 → AES-256 加密存储，密钥独立于数据库文件
- **[单点故障]** Platform 是单点 → 一期可接受，后续考虑 HA；Agent 独立运行不依赖 Platform 持续在线
