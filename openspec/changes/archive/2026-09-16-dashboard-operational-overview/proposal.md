## Why

首页是平台用户进入系统后最常用的运维入口，但当前概览同时拼接数据库统计、Kubernetes 实时摘要和 Alertmanager 数据，存在统计语义不准确、请求失败被静默显示为 `0`、集群查询偏慢以及内容容易超出首屏等问题。现在统一治理首页的数据契约和布局，可以让用户更快判断服务是否需要处理，并避免把“未知”误认为“正常”。

## What Changes

- 修正证书到期统计：只将未来 30 天内仍未过期的证书计入“即将到期”，并单独识别已经过期的证书。
- 修正 Kubernetes 摘要语义：
  - Pod 就绪按 `PodReady=True` 判断；
  - 未就绪指标明确表示 Deployment，而不误称为应用；
  - 检测节点版本是否一致，避免使用任意第一个节点版本代表整个集群。
- 为首页各数据区补充加载中、成功、空数据和失败状态；禁止把读取失败静默降级为 `0`、空列表或“暂无风险”。
- 为 Kubernetes 集群摘要增加短时缓存和可见的部分失败信息，降低首页首次打开和重复进入时的 API 压力。
- 压缩首页布局和列表内容，首屏优先展示状态判断与部署、更新、日志、监控等操作入口；证书和最近操作仅展示有限条目并提供进入完整页面的入口。
- 增加按每个应用最新 Release 聚合的应用摘要，区分运行正常、发布中、发布失败和未发布，支持首页直接判断应用发布状态。
- 补充后端、前端和接口级测试，覆盖统计边界、错误透传、缓存、加载状态、空状态和首屏布局约束。

## Capabilities

### New Capabilities

- `dashboard-operational-overview`: 提供面向运维用户的准确、可诊断且紧凑的首页状态概览与操作入口。

### Modified Capabilities

- `dashboard-audit`: 更新概览页的状态汇总要求，移除不再存在的静态引导假设，并明确首页数据必须反映真实可用状态。
- `k8s-dashboard`: 更新集群摘要的就绪判断、版本一致性、错误表达和缓存行为，并同步首页展示语义。

## Impact

- 影响 `internal/api/system/dashboard_handler.go`、Dashboard 相关 repository/read model 以及证书统计查询。
- 影响 `internal/api/infrastructure/kubernetes/` 的集群摘要处理和 Kubernetes 客户端调用次数。
- 影响 `web/src/views/Dashboard.vue`、Dashboard API 模块、相关样式和测试。
- 可能新增短时内存缓存和摘要错误字段，但不改变现有路由 URL；保留已有指标字段，新增字段向后兼容。
- 不引入新的第三方依赖，不涉及数据库迁移、认证、部署清单或“集群引导”功能。
