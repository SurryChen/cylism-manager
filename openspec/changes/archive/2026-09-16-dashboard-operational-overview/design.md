## Context

首页目前由三个独立请求组成：

- `/api/dashboard`：读取数据库中的服务器、站点、证书和审计摘要；
- `/api/k8s/dashboard`：并行读取所有 Namespace 的 Node、Pod、Deployment 和 Service；
- `/api/monitoring/alerts/overview`：读取 Alertmanager 当前告警。

这种拆分可以避免一个慢接口阻塞整页，但现有实现对部分错误使用零值继续渲染，且 K8s 摘要每次都执行完整集群级 List。前端还使用固定的空状态高度和多组纵向区块，数据增多时无法稳定保持首屏可读。

## Goals / Non-Goals

**Goals:**

- 让首页每个数字都有清晰、准确的统计语义。
- 让加载中、不可用、空数据和真实的零值可以被区分。
- 降低 Kubernetes 摘要的重复查询压力，并保留实时性。
- 在常见桌面视口中优先展示状态判断和高频操作入口。
- 保持现有 URL、主要 API 路径和已有空状态行为的兼容性。

**Non-Goals:**

- 不实现集群引导、节点安装、Tailnet 配置或新的首页业务模块。
- 不把首页改造成完整资源列表；详细证书、审计、告警和监控仍由各自页面负责。
- 不引入全局状态管理、服务端推送或新的基础设施依赖。
- 不改变 Alertmanager 告警规则、证书签发流程或 Kubernetes 资源的业务生命周期。

## Decisions

### 1. 保留三个领域接口，收紧每个接口的数据契约

继续分别调用数据库概览、Kubernetes 摘要和告警概览，避免把不同故障域耦合成一个不可诊断的大接口。`/api/dashboard` 保留现有 `stats`、`expiring_certs` 和 `recent_logs` 字段，并补充过期证书或区块级错误所需的向后兼容字段；`/api/k8s/dashboard` 保留现有指标字段，并增加明确的错误/部分可用信息。

备选方案：新增一个聚合 `/api/home` 接口。该方案可以减少浏览器请求数，但会把数据库、Kubernetes 和 Alertmanager 的故障边界隐藏在一个长请求中，不利于分区渲染和定位问题，因此暂不采用。

### 2. 用领域规则修正统计，而不是在前端猜测

- 证书查询同时要求 `valid_to > now` 和 `valid_to <= now + 30d`，过期证书单独计数；
- Pod 就绪依据 `PodReady` Condition，而不是 Pod Phase；
- Deployment 就绪仍按期望副本与 Ready 副本比较，但首页文案改为“未就绪 Deployment”；
- 节点版本先归一化后检查是否一致；一致时展示版本，不一致时展示“多版本”并引导查看集群页。

备选方案：只修改文案、不改后端统计。这样能快速规避部分误导，但无法解决过期证书和 Running/Ready 的事实错误，因此不采用。

### 3. 错误采用显式状态，禁止静默零值

数据库统计的关键查询失败时返回明确的 HTTP 错误；证书列表、审计列表等非关键区块可以通过区块错误字段让首页保留其他成功数据。Kubernetes 摘要对单个资源查询失败时将对应指标标记为不可用，并返回错误信息或 `partial=true`，前端显示“暂不可用”，而不是 `0` 或“当前暂无风险”。

前端每个区域遵循 `loading → ready / empty / error` 状态机。只有明确收到成功响应后才显示数字；请求尚未完成显示 `—`，失败显示可理解的中文错误提示。

备选方案：任何一个区块失败都让整个首页失败。该方案实现简单，但会让告警正常而数据库暂时不可用时整页空白，运维信息损失过大，因此采用分区错误。

### 4. 在摘要服务边界增加短时 TTL 缓存

在 Bootstrap 创建的 Kubernetes 摘要服务中增加进程内 TTL 缓存，默认缓存 5～10 秒；同一时间的并发请求共享一次刷新结果，过期后由下一次请求刷新。缓存只用于集群摘要，不缓存敏感数据、告警详情或完整资源列表。请求上下文仍传递到实际 Kubernetes 调用，超时和取消不会被缓存为成功结果。

备选方案：每次请求实时查询。它保证绝对新鲜，但首页频繁进入会重复执行五类集群级 List；当前摘要是运维参考数据，短 TTL 更适合性能与新鲜度的平衡。

### 5. 首屏采用“集群概况 + 应用情况 + 入口 + 有限预览”布局

首页将集群规模与环境信息、应用发布摘要、快捷操作和运行检查分开呈现。应用摘要只按每个应用的最新 Release 统计运行正常、发布中、发布失败和未发布，并展示最近一次发布。证书与最近操作只显示有限条目，并提供“查看全部”链接。移除固定的 230px 空状态高度，减少不必要的纵向留白；桌面端首行使用集群概况、应用情况和快捷操作三列，窄屏再退化为单列。

备选方案：保留所有表格并通过页面整体缩放塞入首屏。该方案会损害可读性和可访问性，也无法控制动态数据量，因此不采用。

## Risks / Trade-offs

- [短 TTL 内显示几秒前的集群数据] → 将 TTL 限制在 5～10 秒，并在摘要中保留“最近刷新”或加载状态；资源详情页仍提供实时读取。
- [Kubernetes API 部分失败导致指标缺失] → 返回区块级错误和 `partial` 标记，前端明确显示不可用，不使用零值替代。
- [新增错误字段导致前端旧版本不识别] → 只新增字段，保留原有指标和路径；旧客户端忽略未知字段仍可工作。
- [首屏压缩后小屏可读性下降] → 仅在桌面断点使用紧凑双列，移动端保持单列滚动并保留完整操作入口。
- [统计规则变化造成用户对历史数字的理解差异] → 在接口测试和 UI 文案中明确“未来 30 天”“未就绪 Deployment”等口径。

## Migration Plan

1. 先补充数据库证书边界、Kubernetes PodReady/版本和错误状态测试。
2. 实现摘要服务及 TTL 缓存，并保持现有 API 路径和已有字段。
3. 更新 Dashboard 的状态机、统计文案、有限预览和响应式布局。
4. 运行后端全量测试、前端测试、Go 构建和 Vite 构建。
5. 观察测试环境首页请求耗时和错误展示；如缓存导致行为异常，可将 TTL 配置为 0 回退到实时查询。

回滚方式：回退摘要服务缓存和前端布局提交即可；不涉及数据库结构和持久化数据迁移。
