## Context

`SelectMenu` 已在审计日志筛选中使用，提供自定义触发器、选项列表、点击外部关闭和基础键盘打开行为。当前 `web/src` 还有 73 个业务原生 `<select>`，分布在 25 个视图中。它们不仅有字符串值，也包含通过 `v-model.number` 绑定的 ID、端口、数量和时长；部分还依赖 `required`、`id`、`data-testid`、禁用状态和 `@change` 联动。

本次是纯前端呈现与组件采用变更。现有选项来源、默认值、请求参数和领域状态必须保持不变。

## Goals / Non-Goals

**Goals:**

- 让所有业务选择控件使用同一个 `SelectMenu` 外观和交互。
- 保留原生下拉框现有的值类型、表单必填约束、标签关联、禁用行为、测试钩子和变更回调。
- 以组件测试和页面回归测试覆盖迁移中最容易退化的值和事件契约。

**Non-Goals:**

- 不变更任何选项内容、默认选项、API 请求、领域校验或页面工作流。
- 不增加多选、搜索、远程加载、虚拟列表或第三方选择控件依赖。
- 不重构与下拉框无关的页面布局或视觉系统。

## Decisions

### 1. 扩展既有 `SelectMenu`，不引入第二个选择控件

现有组件已经符合项目的 Design Tokens、图标库和基础交互，直接扩展其契约可避免两套下拉菜单在页面间继续分叉。组件将接受选项数组、占位符、禁用状态、表单必填、标识和可访问性属性，并继续发出 `update:modelValue` 与 `change`。

备选方案是在各页面保留原生 `<select>` 并统一 CSS。该方案无法统一菜单浮层、图标、焦点与键盘交互，也会持续复制页面级样式，因此不采用。

### 2. 以结构化选项保留原始值类型

每个调用点将把原有 `<option>` 转为 `{ value, label }`。组件在鼠标、键盘或内部原生后备控件选择时，按选项对象发出原始值；对于 `v-model.number`，同时识别 Vue 的数值修饰符，避免将 ID、端口、条数和时长退化为字符串。原有 `@change` 处理函数继续接收同类型的选择值。

备选方案是在每个页面的 `@change` 中单独转换数值。它会分散类型逻辑并遗漏直接绑定的字段，因此不采用。

### 3. 同时保留自定义交互与原生表单后备控件

可见的触发器负责列表框交互、焦点状态和键盘打开；内部视觉隐藏的原生 `<select>` 继续镜像当前值、`required` 和禁用状态，用于浏览器表单有效性。组件将把显式 `id` 关联到可见触发器，以保持外部 `<label for>` 的可访问关联；类名和 `data-testid` 保留在组件根节点，供既有布局与测试定位。

备选方案是移除原生后备控件并只使用 ARIA 属性。该方案会失去现有原生必填校验，无法满足无行为回归的目标，因此不采用。

### 4. 分域迁移并以静态检查封口

迁移按根视图、应用、集群、监控、网络、资源和设置域分组。每页仅把选择控件和与其紧耦合的样式/测试改为共享组件，不改动数据加载或提交函数。完成后以 `rg` 检查业务视图不再直接渲染 `<select>`；组件内部的原生后备控件是唯一允许保留的实例。

备选方案是一次性进行跨目录机械替换。页面的选项来源、禁用表达式和事件签名不同，机械替换容易损坏动态选项或数值绑定，因此不采用。

### 5. 以富选项承接上下文选择器

项目与环境选择器需要在选项中同时呈现名称和说明（项目说明或命名空间），但其选择、禁用和键盘行为仍应属于同一组件。`SelectMenu` 的结构化选项支持 `description` 作为第二行文本，并可用 `triggerLabel` 提供收起状态的专用文案；它们不改变选项的原始 `value`。

备选方案是继续保留工作台专用列表框。该方案会重复浮层、焦点、点击外部关闭和可访问性实现，违背全站单一选择组件的目标，因此不采用。

## Risks / Trade-offs

- [数值绑定被字符串化] → 组件测试覆盖 `v-model.number`、对象选项和内部原生变更；页面迁移保留原选项的数值表达式。
- [表单必填或标签关联失效] → 为 `required`、`disabled` 和 `id` 添加组件级测试，并保留后备原生控件的有效性属性。
- [局部宽度或行内布局改变] → 保留调用点的布局类，按需将仅匹配 `select` 的局部 CSS 改为匹配组件根节点或触发器；运行前端构建与相关页面测试。
- [既有测试依赖原生 DOM 查询] → 将测试改为以稳定的 `data-testid` 或 `SelectMenu` 触发器交互，避免耦合实现细节。
- [遗漏业务视图] → 迁移前后分别用 `rg --glob '*.vue' '<select\\b' web/src` 清点，最终结果仅允许 `SelectMenu.vue` 的后备控件。

## Migration Plan

1. 先为扩展后的组件契约编写失败测试，再实现组件兼容能力。
2. 按任务分组逐页迁移并运行聚焦的前端测试，保留每页的原有值和事件语义。
3. 执行前端测试、生产构建、静态下拉框清点、`go test ./...`、`go build ./...` 和 OpenSpec 严格校验。
4. 若迁移发现页面回归，可将该页面恢复为原生控件，组件和其他页面无需回滚；本变更不涉及数据迁移或部署顺序。
