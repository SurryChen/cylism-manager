## Context

Dashboard 的首行由集群概况、应用情况和快捷操作三张卡片组成。当前桌面媒体查询将该网格行限定为 `minmax(220px, 250px)`；快捷操作列表又使用 `flex: 1`、`overflow: auto`，每个入口最小高度为 44px。默认四项入口加上卡片标题、内边距和间距超过可用空间，因此首屏出现局部滚动条。

用户期望首页在常见桌面视口中完整展示。截图所示的宽屏布局有效高度约为 837px，水平空间充足，问题是垂直区域的固定分配而不是信息量或卡片宽度。移动端和极矮窗口仍需要保留自然滚动，不能依赖缩放文字或牺牲触控目标来强行塞入内容。

## Goals / Non-Goals

**Goals:**

- 在常见桌面视口让标题、首行三张卡片、资源趋势和运行检查完整呈现，无页面或快捷操作列表的默认滚动。
- 保持四个默认快捷入口及每项至少 44px 的可点击高度。
- 在宽度不足或高度不足时，以自然页面滚动而非裁剪业务内容的方式降级。
- 以测试锁定桌面和小视口的布局规则，防止以后再次产生默认局部滚动。

**Non-Goals:**

- 不减少默认快捷入口，不改变快捷操作配置功能。
- 不修改仪表盘数据、图表采样、后端接口或运行检查内容。
- 不改变移动端单列布局，也不通过全局缩放、减小字体或减小按钮点击区域解决问题。

## Decisions

### 1. 将首屏尺寸预算落实到父级网格，而非缩小快捷入口

在常见桌面断点中，调整 `dashboard-page` 的行高预算，让首行有足够空间容纳三张卡片的真实最小内容高度，并同步收紧资源趋势和运行检查区域中非必要的垂直留白。快捷入口继续保持 44px 的最小高度。

备选方案是把快捷入口缩小到 36px 或移除默认入口。该方案会降低指针与触控可用性，也让首页丢失高频操作，因此不采用。

### 2. 只在内容确实无法显示的视口允许溢出

常见桌面高度下，快捷操作列表不作为独立滚动区，卡片与首行随其内容获得合理高度。窄屏和极矮视口取消固定的页面高度约束，让页面在文档流中自然延展并由页面本身滚动；局部滚动仅用于动态、不可预期的数据预览区，不用于默认固定的快捷入口。

备选方案是无条件删除所有 `overflow` 规则。这样会使动态应用摘要或活动记录在极端数据量下推动布局失控，因此仅调整默认固定内容的溢出规则。

### 3. 使用明确的 CSS 约束和源级布局测试

使用现有 Design Tokens 和媒体查询表达桌面、窄屏与矮屏规则。先添加能失败的前端测试，验证默认快捷入口的最小点击高度、桌面端不将快捷列表指定为滚动容器，以及小视口保留页面滚动的降级规则；再更新样式使测试通过。

备选方案是仅人工截图验收。截图有价值但不能持续防止 CSS 规则回退，因此将其作为验证补充，不作为唯一保障。

### 4. 首行卡片使用一致的头部与内容节奏

首行三张卡片统一使用相同的内边距、28px 标题栏高度和标题下间距；快捷操作的设置按钮收敛到该标题栏高度。集群概况采用填充可用高度的两行指标和固定底部健康摘要，应用情况采用总数、2 x 2 状态摘要、最近发布三段布局。运行检查保留 12px 正文和状态值，但以已知的四项检查与两条操作预览重新设计行距，常见桌面视口不使用局部滚动。

备选方案是继续通过 `space-between` 或 `margin-top: auto` 把内容推到卡片两端。该方案会在信息较少时制造明显留白，也会使固定高度卡片更容易出现局部滚动，因此不采用。

## Risks / Trade-offs

- [增加首行高度压缩资源趋势或运行检查的可用空间] → 以页面整体首屏高度为预算，限制调整范围，并在常见桌面尺寸验证两个区域仍完整可读。
- [浏览器工具栏、系统缩放使有效高度低于预期] → 极矮视口恢复自然页面滚动，不裁剪任何区块。
- [未来增加快捷入口后再次溢出] → 配置编辑器仍限制并提示合理入口数量；布局测试覆盖默认集合而非假设任意数量都能首屏容纳。
- [不同系统的滚动条显示策略不同] → 验收以内容可见且无溢出为准，不依赖滚动条是否自动隐藏的视觉差异。

## Migration Plan

1. 编写 Dashboard 布局回归测试，复现默认快捷入口在桌面首屏不应形成滚动容器的契约。
2. 调整桌面端行高、卡片与列表溢出规则，并保留小视口的自然滚动降级。
3. 在常见桌面与窄/矮视口运行页面测试和生产构建；人工确认快捷入口、趋势和运行检查均可见。
4. 如出现布局回归，可单独回退 Dashboard 样式改动；本变更不涉及数据迁移或接口兼容性。

## Open Questions

- 无。常见桌面验收以 1440 x 800 及以上视口为基准；小于该高度的环境允许页面自然滚动。
