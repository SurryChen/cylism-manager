## Navigation Model

基础设施保留一级导航。侧栏仅保留按管理对象划分的六个入口：服务器、集群、Kubernetes 资源、网络访问、存储和监控。

聚合入口按页面逐一优化。集群使用单层标题栏，标题右侧平铺节点、节点镜像源和 Chart 仓库。一级视图是同级的日常操作入口，不再使用配置弹窗或二层 Tab。服务器等无切换项的页面复用相同标题栏高度与底部细线，但不保留空白 Tab 区域。

聚合入口的层级如下：

- 集群：节点、节点镜像源、Chart 仓库。
- Kubernetes 资源：工作负载、服务、配置。
- 网络访问：路由、证书。

已有业务视图保持其数据请求和操作逻辑。聚合容器只处理页面标题、页内导航与当前视图选择，避免重复实现资源操作。

## Routing

聚合视图使用新的顶级路由和 `tab` 查询参数表示当前子视图：

- `/cluster?tab=nodes|registry-mirrors|chart-repositories`
- `/resources?tab=workloads|services|configs`
- `/network?tab=routes|certs`

原有的细分地址不再作为独立页面路由，而是重定向到上述新地址。证书签发过程属于证书详情，重定向到网络访问的证书视图。

## Interaction

选择页内 Tab 时更新查询参数，因此刷新、浏览器前进后退和直达链接都能保留当前视图。侧栏仅高亮聚合入口，桌面侧栏不再重复展示当前模块标记。

公共页面标题栏不渲染“当前工作区”等伪元素。无分栏页面的标题左对齐并可保留右侧操作按钮；聚合视图中的无操作子页不重复展示叶子标题。

服务器、存储卷和监控使用共享的无分栏标题栏，固定高度为 52px，包含一致的标题基线、右侧操作区和底部细线。标题栏不承载说明文字，以确保所有页面高度一致。聚合视图标题线与首个内容区之间必须保留固定间距，避免内容卡片与标题线视觉重叠。

存储卷属于基础设施资源。其默认视图必须读取集群内全部 PVC，并展示命名空间、托管来源和工作负载引用；不得要求先选择项目或环境。命名空间、项目、环境、状态和 StorageClass 均为可选筛选条件。平台创建存储卷时直接选择命名空间，创建的独立卷可被同命名空间的应用挂载；外部创建的卷只读展示，平台迁移、导入和备份操作仍仅对已关联环境的托管卷开放。

服务器页提供基本配置与资源监控两个同级视图。资源监控使用一个批量接口并以最多三个并发 SSH 采集服务器 CPU、内存、根磁盘、负载、运行时间和 CPU 核数；采集失败必须显式返回不可达状态，不得以零值代替。前端仅在资源监控视图激活且页面可见时每十秒刷新，未完成采集时跳过下一次刷新；切走视图或组件卸载时停止轮询。资源数据仅为当前采样，不写入数据库。

监控页使用概览、节点、工作负载和诊断四个同级视图。概览优先展示监控状态、可用节点、CPU/内存/根磁盘峰值及各节点趋势；节点视图允许选择节点查看历史曲线；工作负载视图使用 cAdvisor 指标展示高 CPU 与高内存 Pod；采集目标、数据目录、配置同步和原始 PromQL 收敛到诊断视图。历史图表通过受限的 `query-range` 接口读取 VictoriaMetrics 数据，时间范围固定为 1h、6h、24h 或 7d，并由服务端计算起止时间与采样间隔。采集配置为 node、cAdvisor 和 node-exporter 注入 `node` 标签，以使趋势可按节点分组；已安装实例需要在诊断视图同步配置后开始产生该标签。

概览与节点视图不得定时轮询。用户打开页面、切换视图或选择时间范围时才读取数据，顶部刷新命令用于主动重新加载。默认四条趋势通过单一批量接口发起，服务端并发查询 VictoriaMetrics 后返回，诊断目标只在诊断视图加载。趋势查询同时保留 `node` 与 `instance` 标签：历史数据缺少 `node` 标签时，前端使用节点 InternalIP 将 `instance` 回填为节点名，避免聚合为单条无名称曲线。
