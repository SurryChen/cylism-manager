## Why

`/delivery/registry` 同时包含自托管制品库和 Registry Proxy 两个工作区，页面中存在多种透明面板。它们目前依赖全局 `.card`、`.metric` 类和局部 CSS 约定来保持视觉一致，导致页面在需要标题、操作区、紧凑内边距或交互态时重复组合结构，并让后续维护容易再次出现卡面风格漂移。

需要一个只负责玻璃表面和结构插槽的共享组件，使视图继续拥有制品库数据、布局和操作逻辑，同时把卡片的语义、间距与主题适配收口到一个可测试入口。

## What Changes

- 新增无业务状态的 `SurfaceCard` 前端共享组件，提供语义元素、紧凑/常规/无内边距变体、可选交互态，以及标题和操作插槽。
- 组件使用现有玻璃表面 Design Tokens，兼容调色板与减少动态效果设置；不引入硬编码调色板颜色。
- 将自托管制品库和 Registry Proxy 工作区中适合的结构面板迁移到 `SurfaceCard`，保留各自的内容网格、表格、请求、路由和状态处理。
- 将领域专属的 `RegistryProxyWorkspace` 及其测试从共享 `components/` 目录迁移到 `views/delivery/`，使其与制品库工作区同域管理。
- 将审计日志、操作历史和系统设置的既有结构面板迁移到 `SurfaceCard`，让记录与系统入口采用同一受测试保护的玻璃卡片外壳。
- 保留全局 `.card` 与 `.metric`，不进行全站迁移；既有页面可逐步采用组件。

## Impact

- 新增 `web/src/components/SurfaceCard.vue` 及组件测试。
- 新增 `web/src/views/delivery/RegistryProxyWorkspace.vue` 及其同域测试，删除共享目录中的旧文件并更新制品库父视图导入。
- 修改 Registry 两个工作区与对应前端测试。
- 修改审计日志、操作历史及系统设置三个子页面与其前端测试。
- 修改共享组件样式，但不修改后端 API、路由、数据模型或制品库操作语义。

## Non-Goals

- 不创建与 Registry 业务模型耦合的“万能卡片”组件。
- 不将每一条数据记录包装为卡片，也不改变表格/列表的信息密度。
- 不在本变更中迁移 Registry 之外的全部 `.card` 或 `.metric` 使用点。
- 不对现有通用组件进行目录迁移；盘点确认它们不持有单一领域的 API、路由或业务状态。
- 不调整记录与系统的路由、标题层级、筛选、分页、表格密度、设置 Tab 或 KeepAlive 生命周期。
