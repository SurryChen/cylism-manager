## Context

Cylism Manager 是面向小团队运维人员的 NGINX、证书和 K3s 管理控制台。当前 UI 使用 `App.vue` 中的 Soft Tech 令牌、顶部横向导航和全局组件 CSS。页面可用，但页面间存在内联颜色，主题只支持固定的亮/暗两种模式，风险与普通信息缺少清晰层级。

已确认的视觉方向为 Pastel Glass：暖白画布、浅水蓝、浅绿和浅薰衣草配色，辅以克制的半透明面板。它只借鉴配色氛围，不复用任何外部站点的组件结构。

## Goals / Non-Goals

**Goals:**

- 建立可扩展的语义化 Design Token 体系和五套配色，其中默认 Reference Glass 对齐图五。
- 用玻璃化侧栏、工具栏、数据面板和对话框重建全站视觉层。
- 在所有现有页面保留路由、API、筛选、表格、表单和 CRUD 行为。
- 在 375px 移动视口和桌面视口保持可读、可操作的布局。
- 提供可访问的键盘焦点、状态对比和无玻璃效果降级。

**Non-Goals:**

- 不新增后端接口、权限模型、业务数据字段或操作流程。
- 不改变路由 URL、认证流程或 API 响应结构。
- 不把每一行数据包装成独立玻璃卡片，也不使用装饰性渐变圆球或 bokeh 背景。
- 不支持用户自定义任意颜色；本次仅支持经过对比度校验的五套预设配色。

## Decisions

### 1. 使用预设 palette 属性和语义令牌

根应用使用 `data-palette` 属性，值为 `mint`、`blue`、`orchid`、`sky` 或 `night`。每个属性覆盖同一组 `--surface-*`、`--text-*`、`--status-*`、`--action-*` 和 `--glass-*` 令牌；组件只引用语义令牌，禁止直接使用调色板十六进制值。`sky` 使用截图中柔和的天空蓝、云雾白和淡紫背景色带，主操作色保持克制的靛蓝。

选择理由：这使组件结构与颜色独立，能安全扩展配色且保持状态语义稳定。选项会保存至 `localStorage` 的 `cylism-palette`；首次加载没有存储值时，系统深色偏好选择 `night`，否则选择 `mint`。在 Vue 挂载前将属性写入根节点，避免首屏闪烁。

备选方案：继续维护 `theme-light` / `theme-dark` 两个类并增加 accent 变量。该方案无法表达玻璃表面、状态背景和夜间对比度的全套语义，因此不采用。

### 2. 分离主题、基础组件和页面样式

将全局样式拆分为令牌、组件原语和应用壳样式模块，由 `main.js` 引入。页面使用共享类和小型局部布局样式，不再使用内联颜色。主题状态由一个无外部状态库的 Composition API 辅助模块管理，供 App 壳与主题菜单共享。

选择理由：当前全部样式集中于 `App.vue`，不利于页面重写与 token 审计。拆分后可通过搜索验证组件没有硬编码颜色。

备选方案：保留 `App.vue` 中的全局 style。它实现较快，但会继续耦合壳层、组件和主题，不适合本次全站重写。

### 3. 固定工作台卡片、无框工具顶栏与移动抽屉承载导航

桌面端顶部栏横跨应用壳，承载品牌与图五式一级导航：概览、基础设施和记录。左侧导航是独立的固定工作台卡片，只显示当前一级模块的二级入口；它不随右侧内容滚动，也不会因路由激活态改变字重或宽度。顶栏右侧承载环境状态、配色选择和账户操作。桌面顶栏不使用圆角浮动卡片，而是作为半透明无框工具条，仅保留一条低对比度底部分隔线。移动端隐藏一级导航和固定卡片，通过具有焦点管理的抽屉展示全部入口，并保留配色选择入口。

选择理由：一级导航提供与图五一致的全局产品骨架，二级侧栏保持运维入口可扫描且不与顶部重复。七个具体功能入口若全部并列在顶部会拥挤，若同时完整显示在两处则会削弱层级。

备选方案：保留顶部导航。它改动更少，但无法改善信息密度与移动端可发现性，因此不采用。

### 4. 玻璃效果只用于结构性表面，并透出图五几何底图

导航、筛选工具栏、页面数据面板、指标面板与模态框使用低透明度白色表面、明亮的 1px 透光边框、内高光、14px 左右圆角和更强的 `backdrop-filter` 模糊/饱和度。数据表的行采用分隔线与 hover 色，不嵌套卡片。概览采用紧凑指标条和主工作区双栏布局，避免把每一项内容均做成同等权重的长列表。背景精确保留图五的两块宽幅倾斜四边形：上方右侧为 aqua、下方左侧为 mist blue；不使用渐变、圆形发光装饰或 bokeh。

选择理由：玻璃效果为层级服务，同时维持高密度运维内容的可扫描性。

备选方案：让顶栏继续作为第三个圆角玻璃框，或使用全页面纯玻璃/实心 pastel 卡片。前者使工具区显得突兀，后两者分别降低表格对比度或偏离已确认的玻璃方向，因此不采用。

### 5. 默认 Reference Glass 精确匹配图五

保留 `mint` 作为稳定的存储键，但将其呈现名称改为 Reference Glass。该 palette 使用画布 `#eaf1f0`、上方色带 `#c2e4db`、下方色带 `#d8e4f7` 与主操作色 `#22736b`，与本地图五原型保持一致。其余四套 palette 继续作为替代偏好。

选择理由：用户可直接获得经确认的参考方向，同时不破坏已有的本地配色选择。

备选方案：增加新的 palette 键并保留原 Mint Glass。该方案会让默认选择和已有存储偏好产生不必要歧义，因此不采用。

### 6. 使用 Lucide 图标和前端组件测试

添加 `lucide-vue-next` 替换文字符号和 emoji 图标；添加 Vite 兼容的单元测试工具，测试 palette 持久化、应用壳导航和关键主题令牌行为。

选择理由：图标需在不同配色下保持一致的线条和可访问名称；主题逻辑需要防回归测试。

备选方案：手写 SVG 或只做构建验证。手写 SVG 缺乏统一性，只做构建验证无法覆盖主题保存和导航行为，因此不采用。

### 7. 配色菜单脱离玻璃表面堆叠上下文

配色菜单使用 Vue `Teleport` 渲染到 `body`，以固定定位跟随触发按钮坐标，并在窗口尺寸变化或页面滚动时重新计算位置。菜单不依赖卡片或 `backdrop-filter` 产生的局部 `z-index`。

选择理由：玻璃表面会创建堆叠上下文，单纯增大局部 `z-index` 无法可靠覆盖下方表格、模态或页面面板。传送至根层能保证菜单始终在应用内容之上。

## Risks / Trade-offs

- [浏览器不支持 `backdrop-filter`] → 使用 `@supports not` 提供不透明背景、相同边框和文本对比度。
- [半透明叠层降低文本或状态对比度] → 每套 palette 单独定义前景/背景语义 token，使用高对比度状态标签，并在测试矩阵中检查。
- [全站 CSS 重写造成现有 CRUD 行为回归] → 保持模板的数据绑定、API 调用和事件处理不变；每个页面重构前先建立交互测试，再执行构建与手动回归。
- [新增依赖导致安装或构建失败] → 锁定依赖版本并在安装后运行前端测试与 Vite build；如图标依赖不可用，使用现有文本作为临时回退而不阻塞数据工作流。
- [复杂背景影响低端设备绘制] → 仅使用两个宽幅背景层，避免动画；在 `prefers-reduced-motion` 下禁用过渡。

## Migration Plan

1. 在不改变页面业务逻辑的前提下引入测试工具、图标依赖和主题基础模块。
2. 建立五套令牌、玻璃降级和共享组件原语，并通过主题测试。
3. 重写应用壳与导航，验证所有现有路由可达。
4. 按概览、资源管理、记录与登录的顺序迁移页面，逐页验证原有请求和对话框。
5. 在全部 palette 和移动/桌面视口完成回归、Vite build 和项目全量 Go 验证后发布。

回滚策略：所有业务行为和 API 均不变。若出现视觉或导航回归，可回退本变更的前端提交，恢复当前 `App.vue` 样式和导航壳；已保存的 `cylism-palette` 对旧版本无副作用。
